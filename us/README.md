# 两个人的小宇宙

现有 GitHub Pages 网站的独立子站，访问路径 `/us/`。原生 HTML、CSS、JavaScript，无需构建或安装前端依赖。

## 本地预览

在仓库根目录执行 `python3 -m http.server 8080 --bind 127.0.0.1`，浏览器打开 `http://127.0.0.1:8080/us/`。请使用 HTTP，避免直接双击 HTML：浏览器会限制 `file://` 下的模块及存储。开发检查：`npm --prefix us test`。

## 已实现

- 奶油白背景，淡粉与鼠尾草绿评分卡，自绘星点、轨道、爱心及花朵纹样；手机、平板、桌面布局。
- 两张方向明确的评分卡。初始 80 分、总分 0～100；正负整数与必填理由，提交前预览，边界验证。
- 按评分方向、日期查看完整记录；撤销通过新抵消记录完成，原记录保留。撤销同样受 0～100 边界限制。
- 最近 7 天、30 天、全部范围的折线图；点击图例切换曲线；鼠标或触屏查看详情；累计加分、减分、净变化。
- 本机存储、同浏览器多标签同步；JSON 备份与校验导入，导入前确认替换。不会自动写入示例数据。
- 可选的双账号登录、共享云端记录、权限校验与并发写入保护，见下文。

## 修改昵称和初始分数

编辑 `config.js` 的 `names` 和 `initialScore`。`him` 是志炫，`her` 是另一半。初始分只在建立新记录本时使用，修改配置不会改写已有历史。云端模式的初始分以数据库为准。

## 本机模式的数据边界

未配置云端时，记录仅保存在当前浏览器的 localStorage，不具备双人访问权限或跨设备同步。清理站点数据、使用隐私窗口或更换浏览器可能丢失记录，建议定期使用页脚的「备份记录」。JSON 包含完整理由，请自行妥善保存。导入是替换，不是合并。读取损坏数据失败时不会覆盖原数据，并提供下载原始记录的入口。

本机存储依赖站点 origin；从 localhost 切换到 GitHub Pages 前，先备份再导入。启用云端不会自动上传已有本机记录；原数据保留在原浏览器，云端建立新的共同记录本。

## 接入两人私密同步

网站继续由 GitHub Pages 提供，数据和身份验证交给 Supabase。网站只需要项目 URL 和公开 key。访问控制在数据库中执行，不依赖隐藏网址或前端口令。

1. 新建 Supabase 项目，在 SQL Editor 中运行 `schema.sql` 的 `begin` 到 `commit` 部分（仅初始化一次）。
2. 在 Authentication → Users 创建你们两个邮箱/密码账号。确认邮箱已完成验证或创建时设为已确认，并在身份验证设置中关闭公开注册。没有自助注册入口。
3. 将文件末尾两个示例 insert 的 UUID 换成两个账号的真实 User ID，再执行，分别绑定 `him` 和 `her`。最多只有这两个角色。
4. 在项目的 Connect / API Keys 中复制项目 URL 和 **publishable key（或 legacy anon key）**，填入 `config.js` 的 `supabaseUrl`、`supabasePublicKey`。**不要填写 secret key / service_role key。**公开 key 可以进入前端，数据保护来自 RLS 及函数权限。
5. 部署后，两个账号分别登录。双方都能读取共同记录，每人只能给对方评分、撤销自己创建的记录。每次提交会重新读取最新总分，可见页面约每 20 秒更新，回到页面时也会更新。
6. 验证：未登录无法读取；未绑定账号被拒绝；自己不能给自己加分；两个账号分别提交后能看到同样的数据。数据库函数在事务内串行验证分数范围，重复请求 ID 不会重复计分。

RLS 默认拒绝匿名读取；认证用户只可读取自己绑定的成员行及共同记录，不能直接插入、修改或删除。写入仅经过已检查身份、评分方向和边界的 RPC。理由以纯文本显示。

云端配置完成后，页面提供登录、退出和备份；为防止误覆盖双方数据，关闭本机备份导入入口。云端错误不会悄悄退回本机模式。真实登录、RLS、事务和双设备同步须在接入真实项目后验证。

参考：[Supabase 浏览器客户端安装](https://supabase.com/docs/reference/javascript/installing)、[密码登录](https://supabase.com/docs/reference/javascript/auth-signinwithpassword)、[Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)。

## 发布

将 `us/` 目录随现有网站正常提交、推送到 GitHub Pages 即可。无须更改根目录 `.nojekyll`。没有在学术主页增加公开入口；可以直接访问 `/us/`。`noindex` 只用于提示搜索引擎不收录，真实私密访问需要配置云端登录。
